# Unraid deployment

This directory contains the Unraid all-in-one deployment template for AIOS Practice Platform.

The stack runs these services on the Unraid `br0` network:

| Service | Container | Default IP | Port | Notes |
| --- | --- | --- | --- | --- |
| MySQL | `aios_mysql` | `192.168.1.130` | `3306` | database `aios`, user `congke` |
| Redis | `aios_redis` | `192.168.1.131` | `6379` | password protected |
| API | `aios_api` | `192.168.1.132` | `18081` | backend API |
| Admin web | `aios_admin_web` | `192.168.1.133` | `80` | admin frontend |
| User web | `aios_user_web` | `192.168.1.134` | `80` | user frontend |
| MinIO API | `aios_minio` | `192.168.1.135` | `9000` | S3-compatible object storage API |
| MinIO Console | `aios_minio` | `192.168.1.135` | `9001` | MinIO web console |

## 1. Files to copy to Unraid

Create the stack and data directories:

```bash
mkdir -p /mnt/user/stacks/aios
mkdir -p /mnt/user/docker/aios/mysql
mkdir -p /mnt/user/docker/aios/redis
mkdir -p /mnt/user/docker/aios/file_assets
mkdir -p /mnt/user/docker/aios/minio/data
mkdir -p /mnt/user/backups/aios
```

Copy these files from this directory to `/mnt/user/stacks/aios`:

```text
compose.yml
.env.example
deploy.sh
backup.sh
```

Then create the real environment file:

```bash
cd /mnt/user/stacks/aios
cp .env.example .env
vi .env
```

Fill in real values in `.env`. Do not commit the real `.env` file.

## 2. Required `.env` values

At minimum, edit these values:

```env
MYSQL_ROOT_PASSWORD=YOUR_REAL_ROOT_PASSWORD
MYSQL_PASSWORD=YOUR_REAL_APP_USER_PASSWORD
REDIS_PASSWORD=YOUR_REAL_REDIS_PASSWORD
MINIO_ROOT_USER=YOUR_REAL_MINIO_USER
MINIO_ROOT_PASSWORD=YOUR_REAL_MINIO_PASSWORD
AIOS_JWT_SECRET=YOUR_LONG_RANDOM_SECRET
AIOS_MYSQL_PASSWORD=YOUR_REAL_APP_USER_PASSWORD
```

`AIOS_MYSQL_PASSWORD` is used by `backup.sh` only.

## 3. MinIO object storage

The deployment starts MinIO and initializes the default bucket:

```text
Bucket: aios-assets
Console: http://192.168.1.135:9001
S3 API:  http://192.168.1.135:9000
```

If you expose MinIO through a reverse proxy, update these `.env` values:

```env
MINIO_SERVER_URL=https://minio-api.example.com
MINIO_BROWSER_REDIRECT_URL=https://minio.example.com
MINIO_PUBLIC_ENDPOINT=https://minio-api.example.com
```

Recommended reverse proxy targets:

```text
minio.example.com      -> http://192.168.1.135:9001
minio-api.example.com  -> http://192.168.1.135:9000
```

Important: the current Go configuration reads `AIOS_FILE_STORAGE_DIR` for local file storage. The compose file already passes MinIO/S3-style environment variables to the API container, but the backend still needs object-storage adapter code before uploads are actually stored in MinIO.

## 4. First deployment

On Unraid terminal:

```bash
cd /mnt/user/stacks/aios
chmod +x deploy.sh backup.sh
./deploy.sh
```

Check services:

```bash
docker ps | grep aios
curl http://192.168.1.132:18081/healthz
curl http://192.168.1.135:9000/minio/health/live
```

Open in browser:

```text
Admin web:     http://192.168.1.133/
User web:      http://192.168.1.134/
API:           http://192.168.1.132:18081/healthz
MinIO Console: http://192.168.1.135:9001/
```

## 5. Automatic updates

In Unraid, install `User Scripts`, then create a script named `aios-deploy`:

```bash
bash /mnt/user/stacks/aios/deploy.sh
```

Schedule it every 10 minutes, hourly, or daily depending on how aggressively you want the NAS to pull newly published images.

## 6. Backups

Create another User Scripts entry named `aios-backup`:

```bash
bash /mnt/user/stacks/aios/backup.sh
```

Schedule it daily. MySQL dumps are written to:

```text
/mnt/user/backups/aios/mysql
```

Local file assets are mirrored to:

```text
/mnt/user/backups/aios/file_assets/current
```

MinIO data is mirrored to:

```text
/mnt/user/backups/aios/minio/current
```

## 7. Image build workflow

Images are built by `.github/workflows/docker-publish.yml` and pushed to GitHub Container Registry:

```text
ghcr.io/congke1940/aios-api
ghcr.io/congke1940/aios-admin-web
ghcr.io/congke1940/aios-user-web
```

If you switch API domain or reverse proxy, update `VITE_API_BASE_URL` in `.github/workflows/docker-publish.yml` and rebuild the frontend images.

## 8. Rollback

Set `AIOS_VERSION` in `/mnt/user/stacks/aios/.env` to a previous image tag, then run:

```bash
cd /mnt/user/stacks/aios
./deploy.sh
```

Recommended stable tags are Git SHA tags generated by the workflow, for example `sha-xxxxxxx`.
