# Unraid deployment

This directory contains the Unraid deployment template for AIOS Practice Platform.

It assumes MySQL and Redis are already running on the Unraid `br0` network:

| Service | Container | IP | Port | Notes |
| --- | --- | --- | --- | --- |
| MySQL | `mysql_dev` | `192.168.1.130` | `3306` | database `aios`, user `congke` |
| Redis | `redis_dev` | `192.168.1.131` | `6379` | your current Redis uses `requirepass` |
| API | `aios_api` | `192.168.1.132` | `18081` | generated by this deployment |
| Admin web | `aios_admin_web` | `192.168.1.133` | `80` | generated by this deployment |
| User web | `aios_user_web` | `192.168.1.134` | `80` | generated by this deployment |

## 1. Files to copy to Unraid

Create the stack directory:

```bash
mkdir -p /mnt/user/stacks/aios
mkdir -p /mnt/user/docker/aios/file_assets
mkdir -p /mnt/user/backups/aios
```

Copy these files from this directory to `/mnt/user/stacks/aios`:

```text
compose.yml
.env.example
deploy.sh
backup.sh
```

Then create the real environment file:

```bash
cd /mnt/user/stacks/aios
cp .env.example .env
vi .env
```

Fill in real values in `.env`. Do not commit the real `.env` file.

## 2. Required `.env` values

At minimum, edit these values:

```env
AIOS_MYSQL_DSN=congke:YOUR_REAL_PASSWORD@tcp(192.168.1.130:3306)/aios?parseTime=true&loc=Local
AIOS_JWT_SECRET=YOUR_LONG_RANDOM_SECRET
AIOS_MYSQL_PASSWORD=YOUR_REAL_PASSWORD
```

`AIOS_MYSQL_PASSWORD` is used by `backup.sh` only.

## 3. Redis password note

Your current Redis container is started with:

```text
redis-server --requirepass "..." --appendonly yes
```

The current Go configuration reads `AIOS_REDIS_ADDR`, but it does not yet read a Redis password field. If runtime code later starts using Redis, add `AIOS_REDIS_PASSWORD` support in the Go config and Redis client wiring before relying on the password-protected Redis instance.

## 4. First deployment

On Unraid terminal:

```bash
cd /mnt/user/stacks/aios
chmod +x deploy.sh backup.sh
./deploy.sh
```

Check services:

```bash
docker ps | grep aios
curl http://192.168.1.132:18081/healthz
```

Open in browser:

```text
Admin web: http://192.168.1.133/
User web:  http://192.168.1.134/
API:       http://192.168.1.132:18081/healthz
```

## 5. Automatic updates

In Unraid, install `User Scripts`, then create a script named `aios-deploy`:

```bash
bash /mnt/user/stacks/aios/deploy.sh
```

Schedule it every 10 minutes, hourly, or daily depending on how aggressively you want the NAS to pull newly published images.

## 6. Backups

Create another User Scripts entry named `aios-backup`:

```bash
bash /mnt/user/stacks/aios/backup.sh
```

Schedule it daily. MySQL dumps are written to:

```text
/mnt/user/backups/aios/mysql
```

Uploaded file assets are mirrored to:

```text
/mnt/user/backups/aios/file_assets/current
```

## 7. Image build workflow

Images are built by `.github/workflows/docker-publish.yml` and pushed to GitHub Container Registry:

```text
ghcr.io/congke1940/aios-api
ghcr.io/congke1940/aios-admin-web
ghcr.io/congke1940/aios-user-web
```

The frontend image is built with:

```text
VITE_API_BASE_URL=http://192.168.1.132:18081/api/v1
```

If you later switch to a domain name or reverse proxy, update `API_BASE_URL` in the workflow and rebuild the images.

## 8. Rollback

Set `AIOS_VERSION` in `/mnt/user/stacks/aios/.env` to a previous image tag, then run:

```bash
cd /mnt/user/stacks/aios
./deploy.sh
```

Recommended stable tags are Git SHA tags generated by the workflow, for example `sha-xxxxxxx`.
