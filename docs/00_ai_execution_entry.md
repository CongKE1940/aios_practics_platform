# 给 AI 的执行入口说明

你现在接手的是一个名为 **题练通（暂定名）** 的刷题与考试系统项目。你的目标不是“讨论需求”，而是**按文档把项目落地**。

## 你的执行目标
- 依据本交付包完成：
  - 产品拆解
  - 数据库设计
  - 后端服务设计与开发
  - 前端管理端与用户端开发
  - 测试用例编写
  - 验收准备
- 任何实现均必须符合：
  - 一期仅网页端；
  - 二期需可扩展至手机和平板；
  - 租户边界为学校/组织；
  - 管理端给系统管理员与学校管理员；
  - 用户端给老师与学生；
  - 一期仅支持客观题；
  - 必须为二期主观题预留扩展能力。

## 你的开发约束
- 不得跳过权限、多租户、历史快照、题目质疑、导入模板。
- 不得把“熟题过滤”应用于考试场景。
- 不得假设题目只有 4 个选项。
- 不得把题目答案设计成“固定第几个选项”的单一结构。
- 不得将客观题结构写死到无法扩展主观题。
- 不得让低层级直接修改高层级原题；低层级只能质疑/纠错，经上级审核后生效。
- 不得让跨租户数据在接口查询中泄漏。

## 你的交付步骤
### 阶段 1：搭建骨架
- 初始化前端 monorepo 与后端服务骨架。
- 建立统一错误码、权限模型、租户上下文、中间件。
- 建立数据库 migration 与基础字典表。

### 阶段 2：优先实现基础模块
- 登录认证
- 用户/角色/菜单/权限
- 学校/年级/班级/课程
- 公告/通知

### 阶段 3：实现题库主链路
- 题库管理
- 题目编辑与导入
- 标签/评论/质疑
- 题库下发与可见范围

### 阶段 4：实现练题主链路
- 练题配置
- 顺序/随机练题
- 单题库/多题库练题
- 错题/熟题/疑惑题记录

### 阶段 5：实现考试主链路
- 随机组卷规则
- 发布考试
- 考试作答
- 自动判分（客观题）
- 成绩统计

### 阶段 6：实现数据分析与快照
- 管理端看板
- 学生/老师变更历史
- 升级/升学/毕业/离校快照

### 阶段 7：测试与上线准备
- 按验收清单逐项验证
- 补齐导入模板下载、异常处理、空态和权限边界
- 完成上线检查和回滚预案

## 输出要求
- 每完成一个模块，输出：
  - 模块范围
  - 涉及接口
  - 数据表变更
  - 页面清单
  - 测试点
  - 与原文档偏差说明（若有）
- 若发现需求空白，不可自行发明结论，应记录到 `docs/19_open_questions_and_risks.md` 中相应条目。

## Definition of Done
当且仅当满足以下条件，模块才算完成：
1. 页面、接口、数据库与权限规则一致；
2. 空态、异常态、权限不足态都有处理；
3. 日志、审计、快照、导入失败反馈可追踪；
4. 测试案例通过；
5. 与验收清单可一一对应。
