# 待确认问题与风险清单

## 1. 待你确认的问题
1. 学校/组织是否需要“集团总部 + 子校区”的层级型租户？
否
2. 老师是否允许跨租户任教？若允许，数据归属与统计归属如何定义？
否
3. 学生是否允许同一时间处于多个班级或多个组织？
否
4. 题目图片、附件是平台上传到对象存储，还是允许第三方 URL？
会接入minio进行存储或oss，第三方url也要转储到系统本地或oss中
5. 考试是否需要防切屏、设备绑定、IP 限制、摄像头监考等防作弊能力？
暂不需要
6. 公告与通知是否需要站内信之外的短信/邮件/企微推送？
暂不需要
7. 质疑审核是否需要多级审批（如老师 → 教研组长 → 管理员）？
暂不需要
8. 是否存在“公开题库市场/共享题库”需求？
存在，但整理为二期需求；一期仅实现题库授权下发，不实现公开市场、订阅、审核与结算等能力。
9. 课程是否需要按学期、学年区分？
不需要，但要支持设置课程的开始时间结束时间
10. 是否需要支持学生账号由外部系统同步（教务系统/LDAP/企业微信）？
暂不需要

## 2. 技术风险
1. 如果后续主观题较快进入二期，而一期题目结构设计过窄，会导致重构成本高。
2. 如果题库下发采用复制而非授权，版本治理会很快失控。
3. 如果历史快照做得太晚，真实业务变更后难以补回。
4. 如果图片资源没有对象存储规划，会卡住图文题落地。
5. 如果考试链路没有自动保存和幂等设计，会在真实教学场景下产生较高投诉。

## 3. 阶段 0 收口结论
1. 学生同一时间只允许一个 current 班级归属，使用 `student_class_memberships` 记录当前关系与历史流转。
2. 系统管理员归属平台级虚拟租户 `platform`，不再使用空 `tenant_id` 表达系统级数据。
3. 课程需要 `start_at` / `end_at`，但不引入学期、学年模型。
4. 文件上传与第三方 URL 转储先定义统一文件资产接口，具体 MinIO/OSS 连接配置后续补齐。
5. 公开题库市场进入二期需求池，不阻塞一期阶段 1。
