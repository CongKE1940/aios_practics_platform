# 前端代码规范

## 1. 基本原则
1. 页面专注当前功能，一页一功能优先。
2. 业务规则不写在 JSX 中，必须抽离到 hooks / service / utils。
3. 组件能复用再抽象，不能为了“看起来高级”过度封装。
4. TypeScript strict 模式下不得随意使用 `any`。
5. 视觉上遵循“整洁、清晰、居中、留白足够”的要求。

## 2. 命名规范
- 组件：`PascalCase`
- hooks：`useSomething`
- 工具函数：`camelCase`
- 常量：`UPPER_SNAKE_CASE`
- 路由目录：kebab-case 或业务名小写

## 3. 目录规范
每个业务页至少包含：
- `page.tsx`
- `service.ts`
- `types.ts`
- `hooks.ts`
- `components/`（如需要）

禁止：
- 在一个超大文件里混合页面、接口、类型、工具函数。
- 页面直接 import 深层 repository 风格工具而绕过 service 层。

## 4. 组件规范
- 展示组件与业务组件尽量分离。
- 表格列定义拆到独立文件。
- Modal / Drawer 内逻辑复杂时单独文件化。
- 表单字段超过 8 个时，拆分为逻辑分区。

## 5. 交互与布局规范
- 页面主容器最大宽度居中；
- 卡片之间上下间距默认 24px；
- 组件内部间距默认 16px；
- 行内按钮与文字至少保留 8px 空间；
- 提交/保存等主要按钮位置固定且易发现。

## 6. 状态处理规范
页面必须覆盖：loading、empty、error、no-permission。

## 7. API 调用规范
- 所有接口通过统一 request client 发起。
- 统一处理 token 过期、租户头、错误码。
- 列表查询参数必须显式类型化。
- Mutation 后更新 Query Cache，避免全页面粗暴刷新。

## 8. 表单规范
- 表单 schema 与后端 DTO 尽量对应；
- 必填、格式、业务校验分层处理；
- 导入配置页必须给出模板说明与错误反馈入口；
- 题目编辑器必须有保存草稿与保存发布两个清晰动作。

## 9. 题目相关特殊规范
- 选项 key 与显示顺序分离；
- 不得通过数组下标直接判定答案；
- 图片题所有资源 URL 都要走统一上传/预览逻辑；
- 预览组件必须与最终展示组件尽量复用渲染函数。

## 10. 测试规范
- hooks 有输入输出逻辑的必须写单测；
- 页面关键交互（练题提交、考试交卷、组卷校验）必须有 E2E；
- bug 修复应补回归测试。
