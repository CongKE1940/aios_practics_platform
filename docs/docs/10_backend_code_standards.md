# 后端代码规范

## 1. 总体原则
1. 业务清晰优先于技巧炫技。
2. Handler、Service、Repository 职责分离。
3. 事务只在 Service 层开启。
4. 多租户过滤与权限校验不能依赖前端，必须后端兜底。
5. 所有关键业务操作必须可审计、可追踪。

## 2. 包结构规范
- `handler`：参数解析、参数校验、响应封装
- `service`：业务编排、事务、权限判断
- `repository`：数据库操作
- `model`：持久化实体
- `dto`：请求/响应对象
- `convertor`：对象转换

## 3. 方法签名规范
- `context.Context` 必须为第一个参数
- Service 方法命名采用动宾结构，如 `CreateQuestionBank`
- Repository 方法表达数据库语义，如 `ListByTenantID`

## 4. 错误处理规范
- 统一错误码体系，不直接返回原始数据库错误给前端
- 业务冲突使用 409 语义
- 参数校验失败使用 422 语义
- 错误日志需要带 request_id、tenant_id、user_id

## 5. 数据访问规范
- 任何租户级表查询默认带 tenant_id 条件
- 系统级绕过必须显式声明，不允许隐式放行
- Repository 不得做复杂业务规则判断
- 批量写入时注意幂等与唯一索引

## 6. 事务规范
必须在以下场景使用事务：创建考试模板并生成试卷、质疑审核并生成新版本题目、导入任务成功入库 + 结果回写、组织变更 + 快照写入 + 历史写入。

## 7. 领域规则规范
- 熟题逻辑仅在练题模块处理，不得在考试模块复用
- 考试组卷规则必须封装为独立领域服务
- 题目版本更新必须走统一服务，禁止业务方直接 update 覆盖

## 8. SQL 与 Migration 规范
- 所有表结构变更通过 migration 管理
- migration 文件采用时间戳前缀
- 禁止直接在线上手工改表而不补 migration
- 所有新增索引需说明对应查询场景

## 9. 日志规范
### 9.1 必打日志
- 登录失败
- 权限拒绝
- 导入任务开始/结束
- 考试发布
- 质疑审核
- 快照创建失败

### 9.2 禁止日志
- 明文密码
- 完整 token
- 隐私敏感信息裸奔打印

## 10. 测试规范
- Service 层有复杂规则的必须写单测
- Repository 层可对关键 SQL 写集成测试
- 组卷、取题、权限、快照是测试重点
