# PRD：题练通（暂定名）

> 版本：v0.9  
> 日期：2026-04-21  
> 适用阶段：一期网页端 + 二期扩展预留

## 1. 产品背景
面向学校/组织构建一套“题库管理 + 刷题练习 + 考试发布 + 数据分析”的平台。平台既服务管理者，也服务老师与学生。核心目标是：
- 让不同层级可以沉淀和复用题目资产；
- 让老师能够快速发布练习与考试；
- 让学生高效刷题，并沉淀错题、熟题、疑惑题；
- 让管理者掌握学习质量、考试情况和题目治理过程；
- 为后续移动端与主观题扩展预留架构空间。

## 2. 产品目标
### 2.1 业务目标
1. 建立统一的题库资产沉淀与下发机制。
2. 建立支持课程、班级、老师、学生多维度使用的刷题系统。
3. 支持老师按规则随机组卷并发布考试。
4. 形成覆盖练题、考试、质疑、修订、统计的闭环。
5. 建立学校/组织级多租户隔离能力。

### 2.2 成功指标（一期建议目标）
- 有效模板导入成功率 ≥ 99%。
- 常规题库列表/API 查询 P95 ≤ 500ms。
- 练题答题记录准确率 100%。
- 随机组卷规则校验错误可解释率 100%。
- 权限串租户事故 = 0。
- 历史快照缺失导致的数据不可追溯问题 = 0。

## 3. 一期范围
### 3.1 必做范围
- 网页端，分为管理端与用户端。
- 角色与权限、菜单管理、公告、通知。
- 学校/组织多租户，系统级可看全局，租户级仅可看本租户及下级。
- 组织层级：系统 → 学校/组织 → 年级 → 班级 → 学生，并纳入老师、课程。
- 题库：创建、维护、下发、课程关联、混合题型。
- 题型：单选、多选、判断。
- 题目表现：支持文字题干、图片题干、文字/图片选项混合。
- 刷题：顺序/随机、单题库/多题库。
- 题目标签、评论、质疑、纠错流程。
- 熟题、错题、疑惑题记录。
- 考试：老师及以上创建、随机组卷、发布时间控制、客观题自动判分。
- 模板导入：题目、题库、试卷/考试模板下载与导入。
- 快照：升学、升级、毕业、离校、班级变更、教师任课变更。
- 数据分析：错题、练题、考试统计。

### 3.2 二期预留
- iOS/Android/iPad/安卓平板。
- 主观题：填空、简答、论述。
- 图片导入、AI 识别导入。
- 更丰富的考试防作弊机制。
- AI 讲解、知识点推荐、个性化练习。

### 3.3 明确不做（一期）
- 原生移动端实际交付。
- 主观题人工阅卷流。
- AI 自动批改。
- 第三方支付、商城、积分兑换。
- 视频课程系统。

## 4. 用户角色
| 角色 | 使用端 | 核心职责 |
|---|---|---|
| 系统管理员 | 管理端 | 管理全租户、平台字典、菜单、角色、权限、全局统计 |
| 学校/组织管理员 | 管理端 | 管理本租户组织架构、人员、题库、考试、通知 |
| 年级管理员（可选） | 管理端 | 管理本年级题库、班级、考试和数据 |
| 班级管理员/班主任（可选） | 管理端/用户端 | 管理本班学习情况、考试与题库使用 |
| 老师 | 用户端 | 维护题库、发题、组卷、发布考试、处理班级学习 |
| 学生 | 用户端 | 刷题、考试、评论、质疑、管理错题/熟题/疑惑题 |

## 5. 核心业务规则
### BR-001 多租户边界
从“学校/组织”开始是租户边界。系统级用户可跨租户查看，租户级用户只能查看本租户及以下范围数据。

### BR-002 层级关系
系统下可有多个学校/组织；学校下可有多个年级；年级中可有多个班级；班级下可有多个学生；老师与课程为横向关系。

### BR-003 师生课程关系
- 一个班级可有多个老师；
- 一个老师可任教多个班级；
- 一个班级有多门课程；
- 同一班级中的同一门课程仅由一名老师授课；
- 一个学生可学习多门课程。

### BR-004 管理端与用户端边界
- 系统管理员与学校管理员使用管理端；
- 老师与学生使用用户端；
- 老师虽使用用户端，但必须具备“题库管理、考试发布、班级数据查看”等能力。

### BR-005 题库创建与下发
题库可由任意层级创建，且可向下级授权/下发。下级默认只使用，不直接修改上级原始题目。

### BR-006 考试创建权限
考试仅允许老师及以上层级创建与发布。

### BR-007 题目结构扩展性
一期只做客观题，但题目底层结构必须支持二期主观题；因此题目内容、答案、解析应采用可扩展 JSON 结构，而非写死字段。

### BR-008 选项数量不固定
选择题选项数量不可写死为 4 个。答案应以“选项 key 集合/布尔结果”表达，而不是“第几个选项”。

### BR-009 图片题规则
- 题干可为文字、图片或混合；
- 选项可为文字、图片或混合；
- 当题干和选项都为图片时，答案仍以稳定的 option key 表示，不依赖显示位置。

### BR-010 熟题规则
熟题仅影响练题推荐与题目出现，不影响考试题目。

### BR-011 错题/疑惑题规则
错题与疑惑题都要沉淀记录；考试与练题均可能形成错题，但“熟题”只来源于练题主动标记。

### BR-012 随机组卷规则
发布考试时可按：
- 每种题型数量
- 每种题型分值
- 总分
- 涵盖知识点
- 每个知识点每种题型数量
进行随机组卷；如果题量不足，系统必须阻止发布并提示缺口。

### BR-013 导入规则
一期只支持模板导入，需支持模板下载；模板结构应为后续图片导入、AI 识别导入兼容。

### BR-014 快照规则
升学、升级、毕业、离校、转班、教师任课调整等必须生成历史快照，确保历史统计可回溯。

### BR-015 题目质疑与纠错
学生/老师可对不属于自己层级的题目发起质疑与纠错；上级审核通过后，可更新题目版本并通知相关使用者。

## 6. 关键流程
### 6.1 题库下发流程
创建题库 → 审核/发布（可选）→ 选择下发目标 → 目标范围可见与可用 → 下级使用/评论/质疑 → 上级处理并形成版本更新。

### 6.2 学生练题流程
选择课程/题库 → 选择顺序/随机与单库/多库 → 获取题目 → 作答 → 自动判定 → 记录错题/疑惑/熟题 → 输出练题结果。

### 6.3 老师考试流程
配置考试规则 → 预检查题量 → 随机组卷 → 发布到班级/课程 → 学生作答 → 自动判分 → 老师查看统计。

### 6.4 质疑修订流程
学生/老师提交质疑 → 指派上级审核 → 审核通过后更新题目版本 → 下游题库与考试引用关系保持稳定 → 通知相关用户。

## 7. 非功能要求
### 7.1 性能
- 列表页默认分页；
- 大题库列表支持条件筛选与缓存；
- 常见查询结果使用 Redis 缓存；
- 组卷过程需要加锁避免重复计算与并发脏读。

### 7.2 安全
- JWT + 刷新令牌；
- 关键操作审计日志；
- 租户上下文强制注入；
- 文件上传需校验 MIME、大小和来源；
- 管理接口与用户接口分域或分路由隔离。

### 7.3 易用性
- 页面整洁清晰，一页一功能优先；
- 表单与卡片内容居中，组件间保留足够留白；
- 关键操作按钮与周边文字保持明确间距；
- 空态、异常态、导入失败态必须有解释。

### 7.4 可扩展性
- 前端采用 monorepo，共享类型、接口 SDK、工具库；
- 后端按模块解耦，支持二期新增题型与终端；
- 数据结构使用可扩展 content/answer JSON 设计。
