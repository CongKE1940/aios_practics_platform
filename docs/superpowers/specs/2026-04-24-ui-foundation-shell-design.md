# UI 一期设计：平衡型现代教育工作台与双端应用壳

日期：2026-04-24
状态：待审阅
适用仓库：`D:\workspace\projects\aios_practice_platform`

## 1. 背景

当前项目的业务主链路已经基本打通：

1. 管理端已具备组织、题库、题目、导入、用户、权限、公告、数据看板与快照历史等页面；
2. 用户端已具备登录、课程、练题、练题记录、班级学习、学生考试、老师考试与批阅等页面；
3. 登录、考试、批阅、统计等正式 API 与前后端联调链路已经成立。

但从产品完成度看，当前前端仍停留在“功能页拼装”阶段，主要问题包括：

- 两端页面大多直接使用原生标签堆叠，缺少统一视觉系统；
- 登录页、应用壳、导航、卡片、表单、表格、状态标签没有一致的风格；
- 管理端不够像正式后台，学生端/老师端也不够像正式产品；
- 现有页面虽然能用，但视觉层级弱、信息密度不稳、整体上线观感不足。

因此，本轮不继续扩展业务能力，而是进入 UI 一期：先建立统一视觉基座，并完成管理端、用户端的应用壳升级。

## 2. 目标

本轮 UI 一期的目标是交付一个正式可扩展的前端视觉底座，而不是一次性重画全站。

完成后应满足：

1. 管理端与用户端拥有统一的设计语言；
2. 登录页从“裸表单”升级为正式产品首屏；
3. 管理端具备稳定的后台壳层，包括侧边导航、顶部信息区、页面标题区与主内容区；
4. 用户端具备稳定的学习工作台壳层，包括导航、当前用户区、主内容容器与页面头部；
5. 基础控件完成统一风格：
   - 按钮
   - 输入框 / 下拉框
   - 卡片
   - 表格
   - 状态标签
   - 空态 / 错误态 / 加载态
6. 后续练题页、考试页、批阅页可以直接复用本轮建立的视觉系统，不需要重新定义基础样式。

## 3. 范围

### 3.1 包含范围

本轮只覆盖 UI 基座与应用壳，不做深业务重画。

具体包含：

1. 登录页重做
   - 管理端登录页
   - 用户端登录页
2. 管理端应用壳升级
   - 主布局
   - 左侧导航
   - 顶部用户区
   - 页面标题区
   - 内容容器
3. 用户端应用壳升级
   - 主布局
   - 学习导航
   - 当前用户区
   - 页面标题区
   - 内容容器
4. 通用视觉基座
   - 颜色 token
   - 字号与层级
   - 间距体系
   - 圆角 / 阴影 / 边框
   - 通用状态色
5. 通用基础样式组件
   - 主按钮 / 次按钮 / 幽灵按钮
   - 输入框 / 下拉框 / 多行输入
   - 页面卡片
   - 指标卡
   - 信息表格
   - 标签 / 状态徽标
   - 空态 / 错误态 / 加载占位

### 3.2 不包含范围

本轮明确不做：

1. 练题页深度重画；
2. 学生考试页深度重画；
3. 老师考试/批阅页深度重画；
4. 管理端各业务面板的结构性重做；
5. 题干富预览；
6. 移动端专项适配；
7. 图表系统重做；
8. 引入大型设计系统框架（如 Ant Design、MUI、Mantine）。

这些内容属于 UI 二期或后续页面专项改造。

## 4. 视觉方向

### 4.1 已确认方向

本轮采用：

- **B：现代教育工作台**
- 风格倾向：**完全平衡**

含义是：

1. 管理端需要有正式后台的专业感；
2. 用户端需要有学习产品的产品感；
3. 两端共享同一设计语言，不做“后台一套、学生端一套”的割裂式视觉体系；
4. 整体基调保持克制、清晰、现代，不做花哨教育 App 风，也不做冰冷纯数据后台风。

### 4.2 风格关键词

- 清晰层级
- 平衡专业感与亲和感
- 轻卡片，不做浮夸厚重阴影
- 柔和高亮，不做大面积重色压迫
- 信息可扫读
- 正式产品感

### 4.3 色彩策略

主色与中性色以冷静、可信为核心，避免当前项目变成沉重深蓝后台或轻浮学习 App。

建议配色：

1. 主色：
   - 品牌主蓝：用于主按钮、选中态、关键操作
2. 辅色：
   - 靛蓝 / 青蓝轻层次，用于信息强调与局部背景
3. 中性色：
   - 冷灰体系，用于背景、边框、正文、次级文字
4. 状态色：
   - 成功：绿色
   - 警告：橙色
   - 风险：红色
   - 信息：蓝色

约束：

1. 不使用大片深色作为整体背景；
2. 不使用强烈紫色渐变作为主视觉；
3. 不使用米黄、咖色、棕橙作为主体基调；
4. 不把页面做成只有一种蓝色深浅变化的单调界面。

### 4.4 组件观感约束

1. 卡片圆角控制在 8px 左右；
2. 表单控件统一高度与边框风格；
3. 按钮优先图标 + 文字或纯文字，不使用夸张的大胶囊；
4. 标签与状态色统一，不让每个页面自己发明状态样式；
5. 列表、筛选、表格、分页保持密度合理，适合后台和老师高频操作。

## 5. 可选方案与结论

### 5.1 方案一：壳层优先，组件同步起步

做法：

1. 先建立共享样式基座；
2. 同步改登录页、管理端壳、用户端壳；
3. 把卡片、表单、表格等基础样式一起统一；
4. 业务页先吃到新的容器和基础组件样式，不重做业务结构。

优点：

1. 视觉收益立即可见；
2. 后续业务页专项改造成本最低；
3. 最符合当前项目阶段；
4. 能最快解决“页面太丑，不敢上线”的问题。

缺点：

1. 首轮不会把练题页、考试页彻底改到位；
2. 某些旧业务组件会先出现“壳层已升级、内部内容仍较朴”的过渡状态。

### 5.2 方案二：先抽完整组件库，再回填页面

做法：

1. 先做完整 UI 组件层；
2. 等组件稳定后，再逐页替换。

优点：

1. 体系更整齐；
2. 长期复用性强。

缺点：

1. 前期页面可见变化慢；
2. 本轮目标偏产品落地，不适合先投入过多基础设施成本。

### 5.3 方案三：逐页改外观，不抽基座

做法：

1. 直接改登录页、应用壳和几个页面；
2. 以页面为单位修视觉，不建立统一 token 与样式层。

优点：

1. 上手快；
2. 单页见效快。

缺点：

1. 极易再次散掉；
2. 后面改练题页、考试页会重复返工；
3. 不适合当前全站统一升级目标。

### 5.4 结论

本轮采用 **方案一：壳层优先，组件同步起步**。

这是最适合当前阶段的方案：先把“底色”和“骨架”定住，再逐步让高频业务页吃到统一视觉系统。

## 6. 核心设计

### 6.1 技术策略

本轮优先基于现有 React + Vite + TSX 结构直接升级，不引入新 UI 框架。

设计策略：

1. 在现有前端代码中增加共享样式入口；
2. 使用统一 CSS token 与基础类；
3. 通过少量通用组件或通用样式包装，覆盖高频视觉模式；
4. 保持业务逻辑文件边界不被 UI 重构破坏。

原因：

1. 当前项目已经形成大量页面与测试；
2. 引入大型 UI 框架会显著扩大改动面；
3. 本轮目标是产品化升级，不是框架迁移。

### 6.2 样式基座

建议建立统一的样式基础文件，至少包括：

1. `tokens`
   - 颜色
   - 间距
   - 圆角
   - 阴影
   - 边框
   - 字号
2. `reset / base`
   - `body`
   - `button`
   - `input`
   - `select`
   - `table`
   - `a`
3. `utility / surface`
   - 页面容器
   - 卡片
   - 区块标题
   - 表单行
   - 工具栏
   - 状态标签

本轮不追求完整设计 token 平台，只要求足够支持第一批应用壳与基础组件统一。

### 6.3 登录页

#### 管理端登录页

目标：

1. 让管理端首屏更像正式后台入口；
2. 明确组织选择、用户名、密码三段结构；
3. 让错误提示、加载状态、提交动作有清晰层级。

布局建议：

1. 页面整体居中；
2. 顶部显示产品名与简短说明；
3. 表单本身放在清晰边界的主卡片内；
4. 组织选择框、用户名、密码使用统一控件；
5. 错误信息使用统一的状态提示区域；
6. 登录按钮为明确主按钮。

#### 用户端登录页

目标：

1. 与管理端共享组件语言；
2. 气质更友好一些，但不偏花哨；
3. 仍然保留正式教育产品的稳重感。

布局建议：

1. 同样居中首屏；
2. 比管理端更强调欢迎感和学习场景；
3. 表单结构与管理端保持统一，避免双套体验。

### 6.4 管理端应用壳

页面壳结构建议：

1. 左侧固定导航栏
   - 产品标识
   - 一级 / 二级菜单
   - 选中态明确
2. 顶部区域
   - 当前用户
   - 退出登录
   - 必要的页面级操作入口
3. 主内容区
   - 页面标题
   - 页面描述 / 操作区
   - 内容卡片区

设计要求：

1. 导航与内容区层级清晰；
2. 菜单不能再是原生列表堆叠；
3. 内容区宽度、留白、滚动区域要稳定；
4. 空页面也要有完整骨架，不再是裸文本。

### 6.5 用户端应用壳

页面壳结构建议：

1. 顶部品牌与当前用户区
2. 左侧或上方学习导航
3. 主内容区
4. 标题区与页面上下文区

设计要求：

1. 比管理端更轻，但仍保留统一骨架；
2. 导航和内容区不能混在一起；
3. 用户信息区要更清晰，不再像简单标题 + 按钮拼接；
4. 对“我的课程 / 练题中心 / 考试入口 / 班级学习”等入口提供统一导航观感。

### 6.6 基础组件样式

#### 按钮

至少统一：

1. 主按钮
2. 次按钮
3. 轻操作按钮
4. 危险按钮

要求：

1. 高度统一；
2. Hover / disabled / active 状态完整；
3. 支持图标位；
4. 不因按钮文字长短导致布局跳动。

#### 输入类控件

至少统一：

1. 输入框
2. 下拉框
3. 多行输入
4. 复选框 / 开关的基础风格

要求：

1. 标签、输入、说明文案有固定层级；
2. 错误态、禁用态清晰；
3. 不再使用完全裸的浏览器默认样式。

#### 卡片

至少统一：

1. 普通信息卡
2. 指标卡
3. 表单卡
4. 列表卡 / 区块卡

要求：

1. 统一边框、圆角、阴影强度；
2. 页面不能“卡片套卡片”；
3. 主体页面用壳层分区，卡片只承载具体内容块。

#### 表格与列表

至少统一：

1. 表头
2. 行高
3. 斑马纹 / hover
4. 空数据提示
5. 状态列与操作列

要求：

1. 后台可扫读；
2. 不因文字长度导致表格失控；
3. 操作按钮样式统一。

#### 状态与反馈

至少统一：

1. 成功 / 失败 / 警告 / 信息提示
2. 空态
3. 加载中
4. 错误提示

要求：

1. 文案位置稳定；
2. 颜色与图形语义统一；
3. 登录页、列表页、统计页都复用同一套表达。

## 7. 页面落地策略

### 7.1 管理端

本轮先改：

1. `apps/admin-web/src/app.tsx`
2. 管理端登录区
3. 管理端导航区
4. 管理端主内容骨架

并让现有面板页面先被新的容器和卡片样式包裹。

这意味着：

1. 组织管理、题库管理、数据看板等页面首轮先吃壳层收益；
2. 业务内部结构暂不做大重排；
3. 后续若继续做 UI 二期，再专项重画各面板。

### 7.2 用户端

本轮先改：

1. `apps/user-web/src/app.tsx`
2. `apps/user-web/src/login-page.tsx`
3. `apps/user-web/src/menu-nav.tsx`
4. 用户端主内容骨架

并让现有课程页、练题页、考试页先落在统一容器里。

这意味着：

1. 当前页面会先拥有更正式的整体观感；
2. 练题和考试内部交互细节仍留待下一轮专项优化。

## 8. 文件与结构建议

本轮建议新增或调整的内容包括：

1. 前端共享基础样式文件
2. 通用布局样式文件
3. 通用基础组件样式
4. 两端 `app.tsx` 的应用壳结构
5. `menu-nav.tsx` 的导航外观
6. 登录页结构与样式

## 9. 测试与验收

### 9.1 测试范围

本轮以现有测试体系为基础，重点验证：

1. 登录流程未被 UI 改造破坏；
2. 导航点击与页面切换仍正常；
3. 关键交互控件可被测试查询正确命中；
4. 类型检查通过；
5. 全量前端测试通过。

如有需要，可增加少量针对壳层的新测试，但不要求为纯视觉细节编写大量快照测试。

### 9.2 验收标准

本轮完成后，至少达到：

1. 管理端登录页具备正式后台观感；
2. 用户端登录页具备正式教育产品观感；
3. 两端都具备完整应用壳，不再是裸列表与裸文本拼装；
4. 导航、用户区、页面头部、主内容区有稳定层次；
5. 基础按钮、表单、卡片、表格、状态标签已统一；
6. 旧业务页虽然未深改，但整体已不再像“未设计状态”。

## 10. 风险与控制

### 风险一：UI 改造影响现有测试

控制：

1. 尽量保留现有关键文本与 `aria-label`；
2. 先改壳层与样式，再微调测试；
3. 不在本轮同时改业务逻辑。

### 风险二：样式改造过散，后续仍返工

控制：

1. 先建视觉基座；
2. 不走逐页随手修；
3. 统一 token 与高频基础组件。

### 风险三：第一轮想做太多，影响交付速度

控制：

1. 明确只做登录页、应用壳、通用基础样式；
2. 练题页、考试页专项重画后置；
3. 不在本轮引入大 UI 框架迁移。

## 11. 结论

本轮 UI 一期的核心，不是“把所有页面一次画完”，而是先把项目从“功能堆叠界面”升级成“正式产品骨架”。

已确认的最终方案为：

1. 视觉方向：**B 现代教育工作台**
2. 风格倾向：**平衡型**
3. 范围：**登录页 + 两端应用壳 + 导航 + 通用表单/卡片/表格**
4. 实施方式：**壳层优先，组件同步起步**

这会成为后续练题页、考试页、批阅页和管理端各业务页继续产品化升级的基础。
